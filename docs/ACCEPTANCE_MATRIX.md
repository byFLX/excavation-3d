# Acceptance matrix: Excavation 3D

Maps every acceptance test of [plan §12](EXCAVATION_3D_PLAN.md#12-verbindliche-abnahmetests) to its evidence.

- **Automated** – a JUnit test in `neoforge-1.21.1/src/test/java` (run by `./gradlew test build`).
- **Game Test – not run yet** – a Game Test in `neoforge-1.21.1/src/main/java/com/byflx/excavation3d/gametest/ExcavationGameTests.java`, run by `./gradlew runGameTestServer`. The build gate (`test build`) only compiles these tests; it does not run them.
- **In game – open** – needs a client, a dedicated server or two players. Not run yet. A passing build does not replace these checks (plan §12, last paragraph).

Test paths are relative to `neoforge-1.21.1/src/test/java/com/byflx/excavation3d/`. Game Test names are methods of `gametest/ExcavationGameTests`.

## Round 7: tool intent and forward-motion render investigation (2026-10-23)

- Server start and extra-block checks and the client preview use `ToolSuitability.isIntendedFor`. It reads the held stack's `DataComponents.TOOL` rules, matches each rule's block holder set with `BlockState.is`, and delegates intent to the pure `MiningIntent.matches`: a speed rule or a positive drops rule must match. A default mining speed and a denies-drops rule alone do not qualify. This supports vanilla mineable tags and modded tag/direct-block rules. The existing `ItemStack.isCorrectToolForDrops` tier check remains separate.
- An unsuitable start stays a silent vanilla single-block break. An unsuitable extra block stays in the world and counts as `WRONG_TOOL`. The preview immediately clears on a known unsuitable start instead of applying the three-tick miss grace; unsuitable cells are excluded from fill and contour.
- The rendering change removes the override of live model-view/projection state with event matrix arguments. This preserves any camera/shader transforms that exist only in the active state. A forward camera displacement lost from a depth-tested overlay can put it behind the wall, whereas the reverse displacement can put it in front. **That mechanism fits the directional symptom but has not been confirmed in the operator's client.** There is no movement/attack/sprint hiding rule, movement field in `Target`, or explicit overlay frustum culling. StableTarget hysteresis and HUD positioning are unchanged.
- Validation: all production and test sources compile with direct Java 21 `javac` against cached dependencies. 31 focused pure JUnit tests pass (tool intent, stable targets, preview fill, start gate and extra breaks). Direct Java launch of the cached NeoForge GameTest server passed all **15** GameTests, retaining the original 13 and adding `pickaxeOnPlanksMinesOnlyTheStart` and `pickaxeShapeSkipsPlanksAndReportsIt`.
